# 2026-10-20 KNM追加適応試作の実行照合

未知品詞の埋め込み3行40値だけを更新した試作を、既存の専用Rust CPU推論で照合した。
試作は固定したHSD回帰で3語悪化し、不採用。従来の推奨開発候補と公開Releaseを維持する。
エンジン・辞書・結合規則・推論依存は変更していない。

## 条件

Windowsで既存の13役割KNMと同じアクセント辞書を使った。
開始最終段のSHA-256は `b0f516152b9f90cb73bd0fb1fb6bcd202e947f6f29b38385e7b45c28689a81fb`。
試作最終段は `b3cfd9cab0f8e0b5ef0e59c602c404262bead772f86d44b6477137dbe0d87ab7`。
HSDのSHA-256は `a06e69d1c12959eca3e0e2a383acc9824c89858f9ebc1f5bbdbf4d374ba47819`。
準備済みデータのSHA-256は `9c037ac9490dd59dabc96aa9dfcf9daf9bf94ba753112714226a4d2b317ceab4`。

元参照332文・5291語と、その部分集合をHSDへ厳密に対応付けた104文・1265語を評価した。
ほかに未確認LLMの6 viewを含め、Rustの全回帰は442 view。
HSDと元参照は同じ本文を共有する。JSUTは基礎・補助モデルの学習集合とも重なる
再利用回帰で、未知文の精度を示さない。句の型を各語に持つ参照への一致であり、
単語単独の語彙アクセント辞書の正解率でもない。

## 結果

| HSD入力 | 開始候補 | 試作 |
|---|---:|---:|
| 許容ラベル一致 / 1265語 | 349 (27.5889%) | 346 (27.3518%) |
| 曖昧でない核位置 / 903語 | 266 (29.4574%) | 264 (29.2359%) |
| 結合規則後 / 1265語 | 348 (27.5099%) | 350 (27.6680%) |
| 発話完全一致 / 104文 | 0 | 0 |

元参照は5118/5291語 (96.7303%)、曖昧でない核位置は3574/3690語 (96.8564%)を維持した。
元参照の全語でモデル予測と結合後予測の双方が一致した。
結合後だけの上昇を理由に、事前に固定したモデル出力の採用条件を変えていない。

- 13役割と各ファイルのSHA-256、FP32全ビットのKNM往復一致を検証。
- `knm_probe` の最終段5件はargmax一致。logit最大絶対差は `2.861023e-6`。
- `knm_pipeline_probe` の全13モデル、16文195トークンはPythonの予測と一致。
- `knm_accuracy` の全442 viewのraw一致率はPythonと一致。
- 既存の生成対比30文を実HSDからHTS生成まで両bundleで完了。出力変更は2文。
  これらに人手正解はなく、出力の変化を精度改善とは数えない。
- `cargo test --locked -p kotonoha --features neural --lib` は138件成功。
  `cargo fmt --all -- --check` も成功。

保存済み形態素からの照合と、実HSDからの文章処理は別の検査として扱う。
推論には配置済みKNMだけを使い、ONNX Runtimeや通信を追加していない。
今回の測定をmacOS実測とは呼ばない。
